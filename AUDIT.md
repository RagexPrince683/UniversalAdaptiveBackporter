# Initial source audit and stabilization

Audit date: 2026-10-20 (America/New_York). Reference checkout: `a0b0f881`; changes below are uncommitted.

## Assessment

The initial source audit found the defects recorded below. **The Stage A follow-up at the bottom of this document supersedes the original unresolved-finding dispositions and validation snapshot.** This is an established production baseline: remaining experimental or visual gaps are not a requirement for a broad manual multiplayer campaign.

Coverage includes a whole-tree source/configuration inventory and targeted implementation tracing through the authoritative paths. It is not an assertion that every line or every content variant has been manually reviewed, nor that all modern Minecraft mechanics have been reproduced. Static evidence, observed runtime results and remaining acceptance work are distinguished throughout.

## Performance evidence and architectural limits

No profiler, allocation capture or repeatable gameplay benchmark was provided. No FPS/TPS percentage improvement is claimed.

- Concrete tracking previously performed block lookups/conversion attempts for every tracked falling block on each world's START tick: O(dimensions × tracked blocks). It now performs world/block work only for the owning world's entries; the set iteration still occurs per world. The double-removal crash is independently corrected. This is a demonstrated reduction in redundant world operations, not a measured tick-time result.
- Mending previously looped per repair point, potentially repeating a full orb budget per item. The arithmetic repair calculation is constant-time per eligible item, with one conserved budget. Item collection, enchantment and optional Baubles lookup behavior are retained.
- The existing elytra post-world-tick path scans every tracked entity each tick. Sculk's experimental death path scans the full loaded tile-entity list. These are structural hotspots requiring representative profiles before redesign; no speculative world-state cache was added.
- Frost Walker still performs radius/block/entity queries when movement warrants them. Correcting straight-line movement intentionally restores that work. A correctness fix must not be described as a performance improvement.
- Recipe/OreDictionary discovery is mostly initialization work. Smithing and furnace recipe matching remain their existing lookup paths. No indexing was introduced without measured evidence and invalidation requirements.
- Renderer searches found many cached/static resource locations and model instances. The audit does not infer frame cost from import/class counts. Client lighting, particle, subtitle, thumbnail and loading code still need a profiler and real GL context.
- Packet scheduling bounds retained server work and confines gameplay mutation to its owner thread. At queue capacity excess actions are dropped; full-queue behavior and multi-player latency/fairness still need traffic testing. This is not asynchronous world processing and is not an anticheat overhaul.

## Save, identity and portability decisions

No block/item/entity registration names, entity numbers, tile IDs, NBT keys or metadata meanings changed. Furnace integer burn-time compatibility and vanilla functional-block identities from earlier fork fixes remain. Worldgen corrections only change future population; no load-time regeneration hook was added. Existing explored terrain is not intentionally rewritten. Server validation worlds are isolated under ignored `run/server` output, not user saves.

Disabling content registrations in an established save still risks missing mappings. Experimental dimension providers, biome IDs and structure palettes remain higher-risk options. There is no claim that a successful startup validates old-world migration.

Only 1.7.10 exists here. Other legacy/modern runtime targets cannot be compiled or certified from this checkout; the adjacent template repository is not an EFR port. Portability risks are the pervasive native block/entity/metadata classes, direct legacy fields, packed numeric metadata, static config/registry initialization, Mixin descriptors/refmap names, GL11/Tessellator rendering, native population and custom simple-channel packets. Keep gameplay authority and externally important IDs/semantics canonical; implement native adapters or independent target implementations where APIs differ. Pure numeric/tag/recipe-domain code may be shareable after an equivalence audit. Do not force the whole tree into a common module or silently reuse this build's Java/runtime assumptions on other targets.

## Stage A stabilization — 2026-10-21

This exceeds a maintenance fix and needs its own acceptance criteria and recovery testing.
